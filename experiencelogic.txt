WORK EXPERIENCE PAGE — HOW IT WORKS
=====================================

Source of truth: data/experience.json
Build: npm run build:experience  →  generated/experience.json

Jobs, education, honors, logos, skill tags, gallery IDs, and photo paths all live in that JSON file. Edit it, run the build, commit both files.

Photo galleries: data/galleries.json keyed by galleryId (tuhs, social, cn, …). PhotoStack on the page opens a themed dialog. Use kind "img" with src, or "solid" placeholders.


── LINKEDIN CSV (optional) ──────────────────────────────────────────────

Drop an official LinkedIn data-export Positions.csv into:

  data/linkedin/Positions.csv

Then run npm run build:experience. Matching company+title rows update dates, location, and title. Photos, tags, subroles, and galleries stay on the JSON overlay so a CSV refresh does not wipe them. New CSV-only jobs appear as basic entries you can dress up in experience.json.


── ADDING A JOB BY HAND ─────────────────────────────────────────────────

Copy an object in the jobs array. Fields: id, company, title, location, dateLabel, bullets or subroles, tags, category, logo { bg, color, letter }, optional galleryId, photos[], companyHref.


── EDUCATION / HONORS ───────────────────────────────────────────────────

education[] and honors[] in the same JSON. Honors render as a button side-scroll (AwardRail), not a mouse-drag carousel.
