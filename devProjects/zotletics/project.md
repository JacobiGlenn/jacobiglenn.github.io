<p class="project-detail-lead"><strong>Zotletics</strong> is a fitness planning web app built specifically for UCI students. It generates personalized workout plans that only use equipment available in Mesa Court and Middle Earth housing gyms — so every exercise it recommends is actually doable on campus, for free.</p>

<div style="margin:0 0 0.25rem;">
  <span class="project-award">&#127942; Best Healthcare Project — ICSSC WebJam 2025 (as "Anteater Gym Service")</span>
</div>

<p>The app started as a hackathon project at ICSSC WebJam 2025 under the name <em>Anteater Gym Service</em>, where it won Best Healthcare Project. After the competition I kept building. The new version is called Zotletics and is a full rebuild with a much bigger scope: AI-powered workout generation, a social layer inspired by Strava, and a school expansion system that can adapt branding and gym data for any university.</p>

<h2 class="project-detail-h2">What it does</h2>
<p>Students sign up with their <code>@uci.edu</code> email, go through a guided onboarding flow (height, weight, goals, experience level, housing community), and get a personalized weekly workout split. The plan is generated by Claude with the user's full profile as context, constrained to only include exercises possible with the actual equipment in their gym. From there the app handles daily workout logging, a calendar view, and a social feed where friends can share progress and hold workout streaks.</p>

<p>The school expansion system is designed from the ground up to support other universities — gym equipment data, branding, color schemes, and even the app name can be swapped via a school config at signup. UCI ships first, but the architecture is already multi-school.</p>

<h2 class="project-detail-h2">AI workout generation</h2>
<p>The workout generation pipeline works like this: when a user completes onboarding or requests a new plan, a Next.js API route pulls their full profile and workout history from Supabase, loads the equipment list for their selected housing gym, and bundles everything into a structured prompt. Claude returns a JSON workout plan that gets parsed directly into the card UI. For individual exercise swaps, a lighter prompt asks Claude to find an alternative targeting the same muscle group using only available equipment.</p>

<p>A hardcoded algorithm handles the scaffolding — muscle group rotation, avoiding back-to-back overwork, rest day placement — and Claude handles personalization and coaching. The AI companion can also answer questions about form, explain why an exercise was chosen, and adjust the plan based on how the user is progressing, all through a floating chat panel on the workout page.</p>

<h2 class="project-detail-h2">Hackathon origin</h2>
<p>At WebJam 2025 I led the Figma wireframes, built the workout dictionary (the function that maps goals and BMI to exercise selections), implemented the BMI calculation logic, and created the hotlink feature that connects exercise cards to tutorial videos. The team was four people; we built the whole thing in 48 hours and shipped a working demo on GitHub Pages. Winning Best Healthcare Project was a huge surprise given it was the first React project for most of the team.</p>

<p>The hackathon version had one major flaw: it could generate the same exercise multiple times in the same plan due to a broken dedup check. Fixing that was the first thing I did in the rebuild.</p>

<h2 class="project-detail-h2">Reflection</h2>
<p>Zotletics is the first project I have owned end-to-end from initial design through a production-ready architecture. Going from the WebJam prototype to the current build forced me to actually think about schema design, auth flows, and what it means to make a product that is safe and maintainable — not just something that demos well. Writing out the full technical blueprint before touching code is something I learned from the hackathon, where we had too many ideas and not enough structure, and it has genuinely changed how I approach new projects.</p>

<p>The AI integration is the part I find most interesting technically. Getting Claude to return structured JSON consistently, handling edge cases where it goes off-format, and building prompts that account for the user's full context without exceeding token limits is a real engineering problem — not just an API call. This is still very much a work in progress, but it is the project I am most invested in right now.</p>
