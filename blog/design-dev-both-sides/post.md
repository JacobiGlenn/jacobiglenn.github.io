---
title: "What it's like to work on both sides of a product"
date: "01/2026"
excerpt: "Being a UI/UX designer at Commit the Change while building dev projects on the side has completely changed how I think about software."
---
<p>Most engineers I know have never opened Figma for anything other than viewing a spec. Most designers I know have never pushed a pull request. I've been doing both simultaneously for a while now, and it's one of the most useful things I've accidentally done for my career.</p>

<p>At Commit the Change, I design features for the Celebrating Life Community Health Center — a real non-profit serving underserved communities in Orange County. Real users. Real stakes. I build wireframes, clickable prototypes, and component libraries that developers then implement.</p>

<p>On the dev side, I'm building the same kinds of products. PocketZot, Zotletics, CollIDE — all of them went through a design phase before any code was written, specifically because I've learned the cost of skipping that step.</p>

<p>The crossover skill isn't Figma or React. It's the ability to hold the user's experience in your head while making technical decisions. When I'm coding a feature, I'm thinking about hover states and loading feedback. When I'm designing, I'm thinking about what's actually buildable in a sprint. That overlap is where I feel most useful on a team.</p>
